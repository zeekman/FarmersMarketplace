# Escrow fuzzing (CT-27)

Coverage-guided fuzzing of `contracts/escrow` with [`cargo-fuzz`](https://github.com/rust-fuzz/cargo-fuzz).

The `escrow_ops` target runs random sequences of deposit (with optional cooperative and royalty),
release, refund, timeout refund, dispute, resolve, auto-release, stream, `set_coop`,
multisig release and admin-config operations with arbitrary actors and ledger timestamps,
using `soroban-sdk` testutils. After every step it asserts:

1. **Token conservation** — the sum of all holders' balances never changes (CT-02).
2. **Settled escrows are final** — a `Released`/`Refunded` escrow never changes status.
3. **Admin-only config** — admin setters called without admin auth fail and `get_config()` is unchanged.
4. **Fee cap** — a settlement (release, auto-release, resolve, multisig release) pays
   `fee_destination` at most `amount * MAX_FEE_BPS / 10_000` (`MAX_FEE_BPS` = 1000).
5. **Buyer exit** — an `Active` escrow past its timeout can always be refunded to the buyer, for the full amount.
6. **Multisig threshold** — a multisig release only succeeds with at least `threshold` valid signatures
   from the escrow's cooperative (signers are random keys generated by the target).

Not covered yet: `Pause`/`Unpause` and "no farmer payout while paused" (#1710), and `FarmerCancel` (#1725).
The contract has no pause or farmer-cancel entry point yet, so there is nothing to drive.

## Run locally

```sh
rustup toolchain install nightly
cargo install cargo-fuzz
cd contracts/escrow
cargo +nightly fuzz build escrow_ops                       # compile only
cargo +nightly fuzz run escrow_ops -- -max_total_time=600  # fuzz
```

Crashes are written to `fuzz/artifacts/escrow_ops/`. Reproduce one with:

```sh
cargo +nightly fuzz run escrow_ops fuzz/artifacts/escrow_ops/<crash-file>
```

The corpus lives in `fuzz/corpus/escrow_ops/` (git-ignored).

## CI

`.github/workflows/contract-fuzz.yml`:

- **Pull requests** touching `contracts/escrow` run `cargo fuzz build escrow_ops`. This only compiles
  the target, so API drift in the contract fails the PR.
- **Nightly** (and manual dispatch) fuzzes for 30 minutes, uploads the corpus, and on a crash uploads
  the crash inputs as the `fuzz-crashes-escrow` artifact and opens a GitHub issue linking to the run.

> The target needs `contracts/escrow` to compile — blocked on CT-01–CT-03 (the contract source
> currently has duplicated `resolve_dispute` and `set_coop` fragments from a bad merge).
